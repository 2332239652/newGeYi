# 好感增长提速 v2.9.6

## 起因

骰主反馈：**升得太慢**。「每天第一次 +1、同一个项目只能加一次、递减到 0」的结果是
大多数人一天只有 3~5 点，升一档要一周。

## 改之前先把账算清楚（494 条真实评审流水）

```
tag 分布   neutral 241 | pushy 70 | share 45 | humor 39 | care 33
           respect 20 | spam 18 | curious_lore 15 | flirt_early 7 | judge_fail 6
delta 分布 0 → 247 条 | +1 → 152 条 | -1 → 95 条
正向 delta 里面：+1 = 152 条，+2 = 0 条，+3 = 0 条
```

两个结论：

1. **模型从来没给过 2 分**——评审提示词里写着「delta 为 1 或 2，**很少给 2**」，
   它就真的永远给 1。所以光把上限从 2 提到 3 是没用的，不改措辞等于没改。
2. 正向占比只有 **30.8%**（494 条里 152 条），而且散在 5 个 tag 上，
   一个人一天能得分的句子本来就不多。

## 三处改动

### ① 评审给分档位重写（`judge.py`）

以前：`加分（delta 为 1 或 2，很少给 2）` → 实际等于恒给 1。

现在：

```
分量的档（按这一轮对方实际给了多少东西来给）：
- 1：对方只是随口应了一句，没什么内容；
- 2：**大多数正常对话都落在这里**——有具体内容的有来有往；
- 3：高光，一整天里最多一两次：真的让她心里动了一下。
分寸提醒：寻常寒暄给 1 可以，但别把"正常的、有内容的一问一答"也压成 1——
那会让关系永远推不动。也不要把客套话夸成 3。
```

顺带把 schema 和 `parse_verdict()` 的夹紧从 `[-3, +2]` 放宽到 `[-3, +3]`。

### ② 同一标签每天记两次，且**独立计分**（`state.py`）

```python
# 以前
eff = max(0, delta - seen) * stage_factor      # 第 1 次 +2、第 2 次 +1、之后 0
# 现在
if seen >= tag_daily_limit: eff = 0            # 第 3 次起才归零
else: eff = delta * stage_factor               # 两次各按自己的 delta 算，不折损
```

新键 `galgame_tag_daily_limit`（默认 2，调试台可改 1~5）。

### ③ 顺带修掉一处会误导人的注释

`Params.delta_max` 从 2 提到 3，注释里写清"评审给 1~3，这里只做保险夹紧"。

## 实测（同一批 14 条真实消息，用真模型重跑评审）

| | 旧规则 | 新规则 |
|---|---|---|
| 正向条数 | 3 / 14 | 5 / 14 |
| 单次均值 | **1.00** | **1.83** |
| 这批总得分 | **3 分** | **9 分** |

细看几条（都是库里捞出来的原话）：

```
"我在说我是群最笨蛋机器人，而且我家里人平时是这个点送饭的"  旧 0 → 新 2 (share)
"歌伊 可以问一个问题吗 你怎么看待内耗这个行为"              旧 0 → 新 2 (share)
"走之前给歌伊喝牛奶！＃投喂歌伊热牛奶"                      旧 1 → 新 2 (care)
"可是歌伊姐姐身为群最笨蛋机器人，我家里人昨天就已经不给我送饭了" 旧 0 → 新 1 (humor)
"歌伊，能试着想一想吗？"                                    旧 0 → 新 0  (照旧不给)
"我是熠暗的管理者，不是你的开发者"                          旧 -1 → 新 -1 (lie)
```

闲聊照旧 0 分，自我介绍/讲自己的事从 0 变 2，谄媚冒充的身份照样扣——
**涨的是"真的在聊"，不是"嘴甜"**。

## 每日估算

按「一天 20 条消息、得分率约 36%、单次均值 1.83」算：

```
旧：20 × 0.21 × 1.00 ≈ 4 分/天     ← 和骰主说的「3~5 点」完全对上
新：20 × 0.36 × 1.83 ≈ 13 分/天    ← 会被 galgame_daily_cap 的 12 截住
```

对应的升级节奏（认真玩的玩家，每天都能聊满）：

| 阶段 | 门槛分 | 最快天数 | 卡在哪 |
|---|---|---|---|
| 熟人 | 15 | 2 天 | `min_days` = 1 |
| 朋友 | 50 | 5 天 | 分数 |
| 亲近 | 110 | 10 天 | `min_days` = 7 |
| 心动 | 190 | 16 天 | `min_days` = 14 + 事件 A |
| 特别的人 | 280 | 24 天 | `min_days` = 21 + 事件 B |

## 还想更快/更慢，拧这三个（都在调试台，不用改代码）

| 旋钮 | 现在 | 作用 |
|---|---|---|
| `galgame_daily_cap` | [12,12,12,10,9,8] | 每天加分上限。**重度聊天时 12 就是天花板**，想再快直接调 15 |
| `galgame_thresholds` | [0,15,50,110,190,280] | 各阶段门槛分 |
| `galgame_min_days` | [0,1,3,7,14,21] | 各阶段最少"有效日"。后期基本是它在卡，改分没用 |
| `galgame_tag_daily_limit` | 2 | 同一标签每天记几次分 |

⚠️ 只改 `thresholds` 不改 `min_days` 的话，70 天以后就没效果了——后期是天数在卡。

## 回滚

| 改动 | 回滚 |
|---|---|
| 评审给分 | 把 `JUDGE_SYSTEM` 里那三档换回「很少给 2」，并把 `parse_verdict` 夹回 `min(2, ...)` |
| 两次计分 | `galgame_tag_daily_limit: 1`（下次同一标签就只记一次） |
| 完全恢复旧递减 | 需要回滚 `state.py::apply_delta` 的 `eff` 那两行（见上面代码块） |
