# v2.9.14：全挂软降级与探测抖动容忍

## 背景

多渠道服务可能出现短时超时、连接重置或限流。旧流程在候选渠道连续失败后立即通知并锁定兜底，短暂波动也会导致持续降级，需要手动干预。

## 行为变化

- 全挂后先记录待恢复状态，默认等待 300 秒；期间由兜底渠道继续响应，不立即通知或锁定。
- 到期后从用户选择的锚点开始重试；恢复则静默切回，仍失败才通知并锁定。
- 冷却期内重复失败不重置计时；手动切换会撤销待重试状态。
- 最近 90 秒成功过的渠道，其连接类瞬时失败暂不计入连续失败。
- 健康探测将 HTTP 200、429 视为链路可达；连接异常可重试一次。

## 配置

```json
{
  "failover": {
    "retry_before_hold_seconds": 300,
    "failure_grace_seconds": 90,
    "probe_ok_statuses": [200, 429],
    "probe_retry": 1
  }
}
```

将 `retry_before_hold_seconds` 设为 `0` 可恢复立即锁定行为。对应实现和回归覆盖位于 `providers/llm_gateway.py` 与 `tests/test_gateway_failover.py`。
