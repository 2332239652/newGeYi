# 共同经历、约定与剧情篇章（2.10.0）

这项功能让歌伊在隔天继续你们做过的小事，同时区分日常聊天、角色共演、单方回忆和已经成立的约定。它复用原有后台记忆提炼，不增加一轮前台模型请求，不调整模型渠道。

## 怎样形成记忆

正常聊天即可。后台从带真实发送者、空间和回复关系的原文里提取少量经历与约定。正文中的 `[AI]` 等标签只是原文，不会变成歌伊的发言证据。

- 共同经历记录事情、结果、可续接线索及来源时间。对方单方回忆会明确标注，不自动变成共同确认。
- 约定区分提议、已答应、已完成、已取消、已替代；也记录谁承担、条件和原话中的期限。提议或“我可以帮你”不自动视为已答应。
- 没有明确履行证据时，即使已到约定日期，也保留待办状态。聊天中的送出、完成与现实外部动作分开理解；机器人发送接口接受回复不代表用户已经阅读。
- 判断刻意保守。新条目采用本批引用的连续原文短摘，保留条件、期限和结果，不让模型补写细节。新约定需要同句明确的“我答应／我会”等承担表达及“你／我们”等对象；“好，明天陪你去”这类口语接受也可能漏收。
- 转述、假设、不确定的旧事、无关的“成功了”和引用别人的发言，都不足以证明一项约定成立或完成。措辞含糊时可能漏收，用户可以用明确的话再次确认。
- 旧摘要和旧自身记忆没有新证据所需的参与者、空间与状态信息，因此不会批量转成新约定。

每次提炼最多处理两个经历和两个约定变化。回复时按当前话题召回少量内容，合计最多占原记忆预算中的1200字，不在每句话里重复提醒所有待办，也不因召回次数增加而把推测强化成事实。

## 查看和管理自己的内容

在产生记忆的同一聊天、同一篇章内发送：

- `共同经历`：查看自己的经历及编号。
- `我的约定`：查看自己的约定与状态。
- `删除经历 编号`、`删除约定 编号`：删除相应记录。
- `纠正经历 编号 新内容`、`纠正约定 编号 新内容`：修正内容，单次最多400字。
- `完成约定 编号`、`取消约定 编号`：明确更新自己的约定状态。

编号是列表中显示的记录ID，请按原样填写。删除经历也会删除与它关联的约定。

管理仅作用于当前发送者、当前完整会话和当前空间。其他用户、其他群、其他机器人或其他篇章的编号不会在这里可见。已完成、已取消、已替代记录不会被一句普通回忆重新打开；重新约定应形成新的记录。

删除、纠正、完成或取消后，相关旧派生纸条会失效，避免自由摘要继续说“还在等你”。删除和“忘了我”会拦住已经在途的旧提炼，保留其他参与者原始聊天的既有边界。`重置上下文`与删除记忆用途不同：前者清理对话上下文，后者管理长期记录。

## 剧情篇章

日常聊天使用 `chat` 空间；每个剧情篇章拥有独立标识。同名篇章也分别保存，避免另一轮剧情混入当前这一轮。

- `剧情模式开`：当前处于日常聊天时新开篇章；已在篇章中时保持当前篇章。暂停后想回原篇章，请用 `续接剧情`。
- `剧情模式关`：暂停并回到日常聊天，保留篇章。
- `剧情篇章`：查看篇章列表和编号。
- `续接剧情`：恢复最近使用的篇章；也可发送 `续接剧情 编号` 或 `续接剧情 名称` 指定篇章，同名篇章请使用编号。
- `新建剧情 名称` 或 `重开剧情 名称`：另开新篇章，旧篇章继续保留；名称可省略。

空间在消息进入时固定。排队或生成过程中切换篇章，会丢弃过时任务的结果，防止回复和证据落入另一个篇章。暂停后续接同一篇章可以继续查到原有经历；剧情中的一次扮演不会因此变成现实用户档案。

## 首版边界

首版只记录歌伊与一位用户的经历。多方合作、跨群自动分享、后台定时兑现和现实外部任务执行均没有接入。群中记录也按当前用户隔离；新模块不沿用旧跨群事实共享开关。

为避免长消息被切断后丢失末尾否定，分片原文暂不生成新经历或约定。已有旧层长消息提炼仍保留。管理属于本地确定性操作；自然语言提炼来自模型候选与本地证据规则，实际召回质量仍应通过后续真实使用观察。

配置 `memory_episodes_enabled` 默认为 `true`，可以关闭新模块提炼和召回。关闭不会删除已存数据，也不会改动现有渠道、密钥或世界书文件。数据库采用增量建表和兼容字段，旧聊天保留在日常空间；切换篇章不批量搬迁旧历史。
