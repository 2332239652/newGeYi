# 作息（休眠）v2.9.5

## 一句话

睡前 30 分钟开始犯困收尾；睡着之后第一次被叫只应一句「睡下了」，之后完全缄默。

## 三段行为

| 阶段 | 判定 | 她干什么 |
|---|---|---|
| **睡前窗口** | 距离入睡 ≤ `sleep_pre_minutes`（默认 30） | 提示词里追加一段「快到睡觉时间了」：回短、不开新话题、不答应陪熬夜 |
| **休眠时段** | `sleep_window` 内（默认 23:30-07:00） | 不接话、不主动搭话、不调模型；第一次被叫（@ 或私聊）应一句，之后缄默 |
| **醒着** | 其余时间 | 和以前完全一样 |

「缄默」是指**一次模型都不调**——省 token，也避免半夜的输出不可控。

## 配置

```json
"sleep_enabled": true,          // 总开关
"sleep_window": "23:30-07:00",  // 可以跨午夜；起止相同 = 不睡
"sleep_pre_minutes": 30,        // 睡前提醒窗口（0 = 不提醒，直接睡）
"sleep_notice_once": true,      // 睡着只应一句（关掉=每次被叫都应一句）
"sleep_notice_text": "（迷迷糊糊翻了个身）唔……歌伊已经睡下了……有事明天说嘛……",
"sleep_owner_exempt": false     // 主人是否免疫（默认不免疫，跟别人一样睡着）
```

## 控制方式

**调试台**（`配置` 页 → 「作息与休眠」组）：开关、时段、睡前分钟、是否只应一句、
主人豁免、睡着时的回话，都能改，保存即热更新。

**QQ 指令**（骰主）：

```
休眠状态          看现在醒着/睡着、还有多久入睡
休眠开 / 休眠关
休眠时间 23:30-07:00
休眠重置          清掉"本会话已提示过"，让她下次被叫再应一句
```

指令**永远不受休眠影响**——命令在 `commands.try_handle` 里就返回了，走不到路由层的
休眠判断。否则半夜想「休眠关」，自己把自己锁死，只能去改 config.json。

## 三个坑（都有测试钉住）

1. **跨午夜**：`23:30-07:00` 必须按 `start > end` 走 `m >= start or m < end`。
   写成 `start <= m < end` 的话整段作息静默失效，而且**不报错**——半夜她照样秒回，
   你还以为是开关没保存。

2. **提示只一次**：状态记的是「这个睡眠段的起始时间戳」，不是日期。
   记日期的话，23:40 提示过一次、过了午夜换天，00:30 又会再提示一次。

3. **孤儿助手轮**：睡着那句不走 `process_job`，所以私聊的用户轮要在
   `send_sleep_notice` 里补记，否则历史里会出现「她回了句睡下了」但前面没有提问。

## 提示词长什么样

睡前 30 分钟内，system 末尾（紧接时间感知之后）多出这一段：

```
【快到睡觉时间了】
再过一个多小时就到 23:30，那时候你就要去睡了（大约还有 25 分钟）。
从现在开始自然收尾：回得短一点、别再开新话题、别答应陪人熬夜、别接那种一时半会说不完的事。
有人还想继续聊，你就困困地回一句「要去睡啦，明天再跟你说嘛」，不用道歉、也不用解释为什么。
困了就写出来——打哈欠、句子变短、答非所问一点点都行，但别把「我要睡了」当成每句都要重复的口头禅。
```

放在时间感知之后是有意的：**越靠近对话，对这条回复的影响越强**。

## 已知取舍

- 休眠期间**消息照常进旁观窗口和记忆缓冲**（`handle_message` 里在 route 之前就写了），
  所以醒来她知道夜里群里发生过什么——跟自我保护静默的处理一致。
- 群里闲聊不触发「睡着了」那句话，只有 **@ 或私聊**才算「要求对话」。
  否则一个夜猫子群能把「我在睡觉」刷成复读机。
- 睡眠期间**主动搭话完全停**（走不到主动分支）。

## 回滚

| 改动 | 回滚 |
|---|---|
| 代码 | `sleep_enabled: false`，或指令「休眠关」 |
| config.json | `config.json.bak-sleep-20261106` |
| 提示词那段 | 把 `SleepWindow.pre_note()` 的返回值改成空串（只影响睡前语气） |
