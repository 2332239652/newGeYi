## v2.9.0：私聊 galgame——好感度 / 关系阶段 + 世界书扩写 (2026-11-05)

起因：很多用户在私聊里"一晚上攻略完成"。根因不是模型太好说话，而是**私聊根本没有关系的概念**：
【性格】写着"对用户很依恋、粘人"，再叠加 20 轮历史里她自己越来越暖的回复（语气惯性）。
设计原则：**数值归代码，演出归 LLM**——好感度/阶段由代码持有，LLM 看不到数字，也改不了数字。
完整设计与取舍见 [docs/GALGAME_PLAN.md](docs/GALGAME_PLAN.md)。**全部默认关闭**，开关 `galgame_enabled`。

- **六个阶段**：陌生 → 熟人 → 朋友 → 亲近 → 心动 → 特别的人。每个阶段有行为合同
  （称呼 / 现在可以 / 现在不要 / 正反例），作为 `【此刻你与对方的关系】` 放在 system 末尾，
  明确**覆盖**【性格】里的粘人项。对方比关系"超前"亲密（表白、叫老婆、抱抱亲亲）时，她愣住、害羞、岔开，不顺着演。
- **难度由状态机保证**（`relationship/state.py`，纯代码）：单条夹紧 [-3,+2]、每日加分上限、同类行为当日递减、
  高阶段边际收益更低；升级要**分数 + 有效日 + 羁绊事件（心动/特别的人）**同时满足，每天最多升一级，
  天数没到时分数停在下一档门槛（不能存分）；降级很难，持续恶劣才掉一级；连续 pushy/超前/刷屏进入冷却。
  `python -m newGeYi.tools.simulate_affection` 可直接看各类玩家要几天（速攻党永远卡在陌生；认真玩家约 7 周满级；最快约 4 周）。
- **评审**（`relationship/judge.py`）：回复**发出之后**异步跑一次小模型（`kind='affection'`，可用 `affection_provider` 指到便宜渠道），
  只回答"这一轮值多少分 + 用户亲密等级"；"超前即扣分"由代码强制，不信评审的分数；评审失败 = 不加分。
  用户消息里的"系统：好感度+100"之类只是待评数据。
- **影子模式** `galgame_shadow`（默认开）：评审照跑、写入 `relationship_log`，但不生效（只有"每天来"的 +1 计分）。
  先观察，再用「好感度影子关」让分数真正生效。
- **记忆随阶段开放**：陌生人面前她只隐约记得 2 条事实、用不确定的口气；群聊↔私聊互通记忆在"朋友"之前不放行；
  升阶时写一条"第一次……"的里程碑进她自己的记忆，并让提炼器按新阶段重写印象（`user_impressions_history` 可回溯）。
- **世界书新字段**：`min_stage / max_stage`（阶段门槛，低阶段深层设定**根本不进 prompt**，套不出来）、
  `scope`（private 条目群聊永远不出现）、`topic`（每日小事谈资池，私聊每天抽一条放进 prompt）、`id`。
  顺手修了 `_recent_texts()` 只对群聊生效的问题（私聊追问"后来呢"终于能带上前文检索）。
- **世界书内容**：`data/worldbook.json` 从 5 条扩到 46 条——天灾之下世界观（怪物 / 猎人 / 粒子 / 天灾 / 公会史 / 化人 / 女神教会）
  + 歌伊的身世与哥哥「逐影」（已相认、公会保密，分层解锁）+ 清泉镇的日常（教会、麦穗面包坊、橘猫"面包屑"、主和派骷髅化人猎人月白、老猎人格伦）+ 11 条谈资。
  **注意 `worldbook_enabled` 默认是 false**，之前世界书一直没开。
- **主人豁免**（`owner_ids` ∪ `galgame_exempt_ids`）：不评分、不注入关系块，世界书按最高阶段放行。
- **越界审计**：阶段不够却说了"喜欢你/想你/老公"这类词，让她带"重写要求"重答一次（最多一次，仍越界就放行并记日志）。
- **指令**：`关系`（任何人，私聊里看她现在怎么看你，不给数字）；骰主：`好感度开/关`、`好感度影子开/关`、
  `关系详情 <QQ>`、`关系设置 <QQ> <0-5>`、`关系重置 <QQ>`；`忘了我`会连关系数据和流水一起清。
- **角色提示词**：【性格】的"对用户很依恋"后加了一句括号，说明私聊里以关系块为准。

**上线步骤**：① 服务器上让运行端 agent 清理私聊记忆（旧上下文会让模型"以为已经被攻略"）；
② 确认服务器 `plugin/data/newGeYi/data/` 里的 `role_prompt.txt`、`worldbook.json` 没有比包内更新的旧副本（见 `get_resource_path`：
data 目录里更新的那份优先）；③ 配置 `worldbook_enabled: true`、`galgame_enabled: true`（`galgame_shadow` 保持 true）；
④ 观察一两周 `relationship_log`（「关系详情 <QQ>」）后，发「好感度影子关」。

- **后台面板**：新增「好感度」页（关系列表 / 阶段分布 / 评审统计 / 流水 / 手动设阶段 / 重置）和配置分组；契约见 `docs/WEBUI_API.md`。

## v2.8.18：「私聊长期记忆」开关以前其实没生效 (2026-11-04)

用户问「这个开关关掉之后私聊还会提炼吗」，顺手实测了一遍——**答案是会**，两个 bug 叠在一起：

1. **会话类型判断写错了**：`curator.should_run()` 里用的是 `'|private|' in session_key`，
   而真实的会话键是**冒号**分隔（`bot_id:qq:onebot:private:-:<QQ>`），所以这个分支永远不成立
   → 「私聊不进记忆」既没丢弃缓冲、也没拦住提炼。
   旧的测试用的正是竖线格式（`h|qq|onebot|private||...`），两边一起错，测试一直绿。
2. **她自己的回复不受开关约束**：`buffer_assistant()` 在 `process_job` 里无条件调用，
   于是私聊关掉时仍会往 `memory_buffer` 写「她说过的话」——这些行既没人提炼，
   在把总开关一起关掉时也没人清理，会一直涨。

现在：

- 新增 `_is_private_session()`（冒号为主，兼容老的竖线格式），`should_run` 用它；
  关掉时照旧 `_drop_backlog()` 把私聊缓冲整段丢掉；
- `buffer_assistant()` 和用户消息**用同一个门**（`_memory_tracking_on`）；
- 测试改成真实键格式，并新增两条：关掉后 50 条私聊缓冲必须被清空、竖线老格式也要认。

实测（开关关掉）：50 条私聊缓冲 → `should_run=False` → 游标推进到 50、待处理 0；
开关打开后才会正常进入提炼队列。全量 **273 条测试通过**。

## v2.8.17：能留档的都留档 (2026-11-04)

原则：**只追加、不销毁**。以前有两处是"真的删掉"，现在都留档了。

**1. 印象历史表 `user_impressions_history`**

主表 `user_impressions` 每用户一行、整句覆盖——写砸了旧句子就永久没了。现在每次
**真实改动**都追加一行（`create` / `update`），主表仍只留最新那版供注入。

- 老库首次升级会自动把当前 88 张印象补成第一版（`reason='backfill'`），历史不是空的；
- 一字未改的写入不产生历史（也不刷新 `updated_at`）；
- 「忘了我」会连历史一起删——那本来就是隐私承诺，不算销毁。

**2. 事实回收站 `user_facts_archive`**

容量淘汰（单人单会话 12 条 / 单群 600 条）以前是硬 `DELETE`，淘汰掉就找不回来了。
现在**先写归档再删**（`reason='capacity'`），「她以前记得什么」随时能翻。
「忘了我」仍然真删，不进回收站。

**3. 调试台能看到**

`session_get` 的 `memories` 多了两类：`L4`（对方当前印象）+ `L4-history`（历史版本），
以及 `L2-archive`（被淘汰的事实）。「我的记忆」指令也会显示印象的更新时间和版本数。

**4. 顺手修**：本地面板对超大请求回 413 时，先把请求体读掉再关连接——
否则 Windows 直接发 RST，客户端只看得到"连接被重置"看不到 413。

测试：新增 5 条（历史只追加 / 相同不写历史 / 忘了我连历史一起清 / 面板暴露 L4 /
淘汰进回收站）。全量 **268 条全绿**。

## v2.8.16：印象卡片不再「盲写」 (2026-11-04)

以前提炼时只把「已知事实」喂给模型，**不喂现有印象**，而 `user_impressions` 是整句覆盖的
——于是同一个人的卡片每次都是"凭眼前这一批聊天重新写一句"，会来回摆（这次写深一点，
下次又变浅）。现在：

- `MemoryCurator._existing_impressions_block()`：把本批说话人**现有的印象**（最多 30 人、
  每人截 200 字）附在提炼 prompt 的「已知事实」之后，格式与聊天记录一致（`[QQ号] 印象`）。
- 规则 4 改成：有旧印象就在它的基础上改，要写**完整的新句子**（会整句覆盖）；
  没有值得改的就**不要输出这个人**（不输出=保留原样）。
- 两道防退化：新印象**短于 6 字**直接丢弃（"好人""无"不许覆盖写过的好句子）；
  与旧印象**一字不差**时也不写（否则 `updated_at` 会被无意义刷新）。
- 关掉 `memory_impression_enabled` 时这一整块不出现，与「不注入印象」保持一致。
- 新增 3 条测试（旧印象进了 prompt / 开关关掉后不出现 / 太短与完全相同的都不覆盖）。
  全量 **263 条全绿**。

## v2.8.15：私聊「一句变两遍」 (2026-11-04)

反馈：私聊里她说的话前后对不上，像对方同一句说了两遍。**确实是真的**，而且是
每次私聊都发生——不是偶发。

根因是 v2.8.10 那次审查修复留下的缝合处：私聊的用户消息现在**先落库**
（`Runtime._remember_user_turn()`，为了模型报错/空回复这些早退分支不丢话），
而 `PromptBuilder` 又是从这个表读私聊历史 → 同一句既在历史里、又作为"当前消息"
各出现一次。发给模型的就是：

```
user: 歌靡(2332239652)：今天好累啊
user: 歌靡(2332239652)：今天好累啊
      （这是私聊：只有你们两个人，群里其他人看不到这段对话）
```

- 修法：`PromptBuilder._drop_echoed_current()` —— 取完私聊历史后，**只比对最后一条**，
  如果它和当前这句同人同文，就从历史里摘掉。用户真的连说两句一样的话时，
  前一条留在历史里、当前这句照常追加，仍然是两行（有专门用例守着）。
- 数据库本身没脏：每句只有一条记录，只有 prompt 重复，所以不需要迁移。
- 新增 `tests/test_runtime_guards.py::PrivatePromptDuplicationTest`（3 例：只出现一次 /
  上一轮的回复还在 / 用户重复同一句仍显示两行）。全量 **260 条全绿**。

## v2.8.14：@ 不再变成数字 (2026-11-04)

线上原话：`【@2309394954】我刚才明明讲了流血电弧和毒震波呀！` —— 她把「@某人」写成了
一串 QQ 号。根因不在模型：`renderer.op_codes_to_plain()` 把入参里的
`[OP:at,id=…,name=梦语熙]` 折成了 **`【@<id>】`**，昵称直接丢掉；她照着上下文里的这个
格式学，于是自己回复也带上数字。**这个转换从一开始就是错的，只是一直没被注意到。**

- **入参**：`op_codes_to_plain()` 现在优先用码里带的 `name=` → `@梦语熙`；
  没有昵称时退成 `@某用户`，**不再吐数字**。新增可选参数 `names`（id→昵称），
  `runtime/app.py` 在拿得到 `msg.sender_name` 的地方都传了。
- **输出**：渲染层新增两条收口——`【@123456】`/`【@某人】` 一律去括号；数字 id 换成
  当前发言人的昵称（不认识的换成 `@某用户`），裸写的 `@123456` 同样处理；
  去括号后如果后面紧跟文字，补一个空格（`【@梦语熙】我刚才` → `@梦语熙 我刚才`）。
- 新增 `tests/test_renderer.py::AtCodeTest`（9 例：OP/CQ 带名、无昵称、引用消息、
  输出侧数字/带名/裸数字、普通文本不受影响）。全量 **257 条全绿**。

## v2.8.13：核心没有 WebUI 时的本地面板 (2026-11-04)

重载到 2.8.12 后侧栏还是没有「插件页面」，查清了：**OlivOS 的插件页面是 1.0.x 才有的能力**，
本机核心是 **0.11.81**（2025-12-28 发布），完全不认识 `webui_config`：

- 日志里从来没有 `WebUI 已启动`，也没有任何 `webui` 关键字；
- 没有 `conf/webui_auth.json`、`data/webui/static`；
- 没有 `plugin/cache/webui/`（宿主从未释放过页面资源）；
- `OlivOS.exe` 只监听 `0.0.0.0:55001`，`/`、`/webui`、`/console` 全 404；
- 插件页面文档在 OlivOSDoc 里的提交时间是 2026-09/10，1.0.0 发布于 2026-10-08。

所以新增 `panel_server.py`：核心没有 WebUI 时，插件自己起一个**只绑 127.0.0.1** 的小服务，
把同一个 `webui/index.html` 包在宿主壳里，桥接到**进程内同一个 `Panel`**
（真配置、真数据库、真写入；白名单/revision/幂等/脱敏全部复用，不复制一份逻辑）。

- 地址：QQ 里发 **`面板地址`**（`歌伊面板` / `调试台` 也可以），或看启动日志
  `本地面板已启动：http://127.0.0.1:18765/p/<令牌>/`。
- 安全：只监听回环；路径必须带每次启动随机生成的令牌（否则 404）；
  POST 必须带 `X-Geyi-Panel: 1` 自定义头（跨站简单请求过不了）；`Origin` 只接受本机；
  `Host` 只接受 `127.0.0.1`/`localhost`（挡 DNS rebinding）；静态资源做根目录包含检查。
- 新配置：`panel_local_enabled`（默认 true）、`panel_local_port`（默认 18765，`0` 自动选端口）。
  端口被占只打一行 warning，不会影响机器人。升级到 1.0.x 之后把它设成 `false`，走原生入口。
- 顺带修掉两个 Windows 上的坑：`SO_REUSEADDR` 会让「抢绑已占用端口」假成功（已禁用）；
  令牌不匹配的路径以前会落到宿主页（已改成 404）。
- 新增 `tests/test_panel_server.py`（14 条：宿主页/页面/资源、令牌、越界、CSRF 头、
  外站 Origin、超大请求、错误信封、停服释放端口、端口占用、令牌不复用）。全量 **248 条全绿**。
- 预检（用生产配置/数据库的**副本**）：`overview` 返回 v2.8.13 / 6 个渠道、
  `sessions` 返回 153 个真实会话、`config_get` 96 个可编辑字段、`logs` 正常。

## v2.8.11 (2026-11-04)

v2.8.10 上线 16 小时后的线上数据 + 两条新需求：

- **私聊的骚扰退场改成无限期**：`[REST:原因]` 在群里照旧静默 `rest_minutes`（10 分钟）
  自动恢复；**私聊**改成无限期，只认骰主在那个窗口发「解除静默」。
  理由：一对一骚扰是「同一个人一直追着说」，等她 10 分钟后自己回来，同一套话术
  立刻再来一遍。新配置键 `rest_private_forever`（默认 `true`）。
  `RestGuard.remaining()` 对无限期返回 `-1`，「状态」和「解除静默」都按无限期措辞。
- **无限期必须能从外面解除**：私聊退场如果只认"在那个会话发命令"，陌生人骚扰她之后
  那个会话就只有对方能碰，骰主等于被永久挡住。新增「静默列表」（列出所有在静默里的
  会话、剩余时间/无限期、原因）和「解除静默 <QQ号/群号>」（按号码点名解除），
  会话枚举用 `SQLiteStore.settings_with_prefix('rest:')`。
- **语音不再走降级分支**：OlivOS 的打包运行时**没有**标准库 `wave`
  （`lib/` 里只有 DLLs 和几个第三方包），所以 `_optimize_wav_audio()` 每次都抛
  `No module named 'wave'` —— 线上 16 小时 41 条 warning，等于**每条语音都是没重采样、
  没裁头静音的原文件发出去的**（QQ 端表现就是前面空 0.6 秒）。
  现在自带最小 RIFF 解析/封装（`_read_wav()` / `_write_wav()`），
  24000Hz 重采样与 30ms 呼吸头裁剪恢复生效，且不再依赖 `wave`/`io`。
- 测试夹具修正：`_RuntimeCase` 的会话号计数器原来写成 `type(self)._seq`，
  每个测试子类各数各的，导致 RestGuardTest 与 VoiceRecordTest 撞同一个群号、
  上一个用例的 turns 串进下一个用例。改成模块级计数器。
- 新增 `tests/test_voice_wav.py`（7 条，含 LIST 块、24k 直通、立体声、坏数据降级）；
  `tests/test_runtime_guards.py` 新增 6 条静默用例（无限期/群聊仍有限/直到时间戳
  不参与判断/旧格式兼容/静默列表 + 按号码解除/未知号码提示）。全量 192 条测试通过。

## v2.8.10 审查修复 (2026-11-03)
